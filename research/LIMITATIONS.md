# Current v2 status

V2 adds real laboratory crypto and retained native proofs, with explicit limits: offline declared domain, self-authorized research keys, no independently observed external admission or historical execution, public one-op arithmetic, no soundness/privacy theorem, no upstream judgment or ReceiptOS production bridge, no durable replay service, two surviving mutants, and no established novelty. Native full recomputation is part of verification. See [artifact boundaries](chain-v2/ARTIFACT_FORMATS.md). Earlier v0 limitations follow.

# Limitations

- Original archive not located. No original SHA-256, original tests, original nine-case inventory or original mutation claims were verified. This is a fresh reconstruction.
- All evidence is synthetic. Checksums are public; catalog membership is a trusted test oracle. No real signature, zkIE proof, EVM call, on-chain transaction or external execution receipt is produced or verified.
- VERIFIED describes the finite synthetic policy. It does not establish input origin, authentic real-world identity, sound judgment, secure inference or actual execution. Real mode always returns UNVERIFIABLE.
- A is intentionally incomplete. It is not any upstream implementation; measured false authorizations demonstrate the weakness of this chosen comparator only. B's selected negative cases are not an estimate of general security effectiveness.
- Eight removal mutants cover eight designed boundaries. Zero survivors in this set is not comprehensive mutation coverage. Tests and implementation share an author and model; independent checkout/re-execution is operational independence, not independent design or audit.
- Scope is literal set inclusion; strength has a synthetic-only ceiling. No general theorem, full semantic entailment, cross-chain authority resolution or arbitrary dependency DAG is implemented.
- Replay is checked against a fixed caller-supplied consumed-nonce list. There is no atomic authorization/consumption or persistent anti-replay service. Time is an explicit fixture value, not a trusted clock.
- The identity sanitization toy is not the ERC-8299 keccak256/CID pipeline. Our restricted integer/ASCII JSON canonicalization is not RFC 8785 JCS. No cross-format hash equivalence is assumed.
- Python runtime and policy integrity are trusted. The evaluator is a research API, not a hardened untrusted-input service, production authorization layer or complete schema implementation.
- Runtime data is local microbenchmark evidence, excludes real cryptography, network, storage, execution, startup and artifact parsing. Timings vary with host load. Ratios are not upstream performance claims.
- Current primary sources were inspected at exact pins, but upstream builds, test suites, deployed gateways and chain state were not independently verified. Open ERC text remains a draft; interface comments may differ from draft prose. See source review.
- Git and SHA-256 inventories establish repeatable bytes relative to published commitments, not publisher trust or semantic correctness. Evidence manifests intentionally exclude themselves to avoid self-reference.
